# 09. 오브 — 부르면 반응하는 화면

> 상태: **동작 확인 완료.** 브라우저에서 네 상태 모두 렌더링을 검증했다.

레퍼런스 자비스들이 이름을 부르면 화면이 반응한다. 그게 장식처럼 보이지만,
음성 인터페이스에서는 기능이다.

## 1. 왜 필요한가

음성에서 **침묵은 두 가지를 뜻한다.**

- "못 들었다"
- "듣고 생각하는 중이다"

사람은 이 둘을 구분하지 못하면 곧바로 다시 부른다. 그러면 JUNVIS는 답하는
도중에 새 발화를 받고, 사용자는 자기가 말을 끊었다는 것도 모른다. 화면 하나가
이 문제를 통째로 없앤다.

그래서 `Presence`는 로그가 아니라 **도메인 개념**이다.

| 상태 | 언제 | 화면 |
|---|---|---|
| `ASLEEP` | 대기 | 어둡고 느리게 회전 |
| `AWAKE` | 이름을 들었다. 후속 발화 창이 열려 있다 | 밝아지고 입자가 모인다 |
| `THINKING` | 명령을 실행하는 중 | 회전이 빨라진다 |
| `SPEAKING` | 답하는 중 | 파동이 퍼져 나간다 |

게이트가 이미 이 전이를 전부 알고 있다. 새로 계산하지 않는다.

## 2. 오브는 아무것도 결정하지 않는다

```
listen 프로세스                        orb 프로세스
─────────────                        ────────────
HandleUtterance
  └ PresencePort.show(THINKING)
       └ FilePresence
            └ ~/.junvis/presence.json ──→ read_presence()
                                              └ GET /state ──→ 브라우저
```

`PresencePort.show()`는 **아무것도 돌려주지 않는다.** 판단에 끼어들 수 없다는
뜻이다. 화면이 꺼져 있어도, 죽어 있어도, 예외를 던져도 명령은 그대로 실행된다
(테스트 `test_a_broken_screen_does_not_break_the_command`).

거꾸로도 마찬가지다. 오브는 `listen` 없이도 뜬다. 상태 파일이 없으면 잠든
모습으로 돈다.

### 왜 파일인가

`listen`과 `orb`는 다른 프로세스다. 소켓이나 큐를 쓰면 듣기가 화면의 존재에
의존하게 되는데, 그건 순서가 거꾸로다 — 화면은 없어도 되는 것이다.

쓰기는 원자적이다(`os.replace`). 오브가 반쯤 쓰인 JSON을 읽으면 화면이
깜빡인다.

상태에는 시각이 함께 적힌다. 90초 넘게 갱신이 없으면 오브는 잠든 것으로
본다 — `listen`이 죽었는데 화면만 깨어 빛나고 있으면 그건 거짓말이다.

## 3. 쓰는 법

```bash
junvis orb                    # 브라우저가 열린다 (127.0.0.1:4173)
junvis orb --port 4174        # 포트가 겹칠 때
junvis orb --no-open          # 브라우저를 열지 않는다

junvis listen --native        # 다른 창에서. 오브가 반응한다
```

`JUNVIS.command`에서 "듣기"를 고르면 둘이 함께 뜨고 함께 내려간다.

`127.0.0.1`에만 묶는다. 개인 기억이 오가는 물건이므로 같은 네트워크의 다른
기기에서 열려서는 안 된다.

## 4. 만들면서 잡은 버그

두 개 다 화면을 그냥 보고서는 원인을 알 수 없었다. 브라우저 콘솔을 열어서
찾았다.

**하나. 음수 반지름이 애니메이션을 통째로 죽였다.**

`speaking`일 때 파동 셋을 시차를 두고 내보내려고 `life`를 `0, -0.18, -0.36`으로
넣었다. 그 값이 그대로 반지름 계산에 들어가 `arc()`가 예외를 던졌고, 예외가
`draw()` 밖으로 새면서 `requestAnimationFrame`이 다시 걸리지 않았다. 화면이
그 프레임에서 영영 멈췄다.

고친 뒤에도 `frame()`에서 `try/catch`로 감쌌다. 장식 한 조각이 실패해도
화면은 계속 돌아야 한다.

**둘. 보간이 프리셋을 덮어썼다.**

```js
let mood = MOODS.asleep;        // 참조를 그대로 들고 있었다
mood[key] += (target[key] - mood[key]) * 0.05;   // MOODS.asleep을 망가뜨린다
```

한 번 다른 상태로 가면 `MOODS.asleep`이 그 값으로 물들어, 다시 잠들어도 원래
모습으로 돌아오지 못했다. `{ ...MOODS.asleep }`로 복사해서 해결했다.
